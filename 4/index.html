A.2: Recover Homographies

Setting Up the System

A homography maps a point (x, y) in one image to (x′, y′) in another:

[w·x′]   [a  b  c] [x]
[w·y′] = [d  e  f] [y]
[ w  ]   [g  h  1] [1]

x′ = (ax + by + c) / (gx + hy + 1)
y′ = (dx + ey + f) / (gx + hy + 1)

Multiplying through by the denominator makes each equation linear in the 8 unknowns. Every correspondence gives two rows:

[ x  y  1  0  0  0  −x·x′  −y·x′ ]   [a]     [x′]
[ 0  0  0  x  y  1  −x·y′  −y·y′ ] · [b]  =  [y′]

In terms of speed, bilinear is around 4x slower than nearest neighbor. However, it makes up for this by improving image quality, as it significantly reduces aliasing due to the way it samples its surrounding pixels, rather than sampling the closest pixel in the reference as nearest neighbor does.

Procedure

I used a one-shot approach, using the middle image as the reference when there was an odd number of images, and arbitrarily picking the right image when there were two. For all warps, I used bilinear warping, as it gave the best-quality images, which would be important during alignment and weighted averaging. I then combined all the images in one canvas that would fit all of them, adding up their respective colors and dividing them by the weighted alpha mask, or how many pixels combined to make that pixel. This did a relatively good job of stitching, but some artifacts, such as blurring, parallax, and visible edges, are still visible.
